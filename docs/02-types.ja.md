# 型システム

Quarz は静的型付きです。クラス・モジュール・メソッドの構造がコンパイル時に確定し、メソッド呼び出しはすべてコンパイル時に解決されます。ただし Ruby らしい書き心地を保つため、メソッドの境界以外では型を書く必要がほとんどないように設計しています。

設計方針:

1. **メソッドの境界では型を書く、中では書かない。** 引数型と戻り値型は書き(戻り値型のないメソッドは `-> Void` で、nil を返す)、ローカル変数は推論。これにより、コンパイル時間を短く、エラーメッセージを分かりやすく保てます。
2. **nil は普通の型の値ではない。** `String` 型の値が `nil` であることはなく、`nil` を取りうるなら `String?` と書きます。
3. **合併型とフロー型付け。** `Int | String` のような合併型を直接扱え、`if`/`case/in`/`is_a?` で絞り込めます。
4. **不変なものは共変。** 不変コレクションは要素型について共変なので、`Array[Int]` を `Array[Int | Nil]` として渡せます。

## 1. 型の構文

| 型 | 例 | 説明 |
|---|---|---|
| クラス・モジュール | `Int`、`String`、`Comparable[T]` | 名前的(nominal)型 |
| ジェネリクス | `Array[Int]`、`Hash[String, Int]` | 角括弧で型引数 |
| nil 許容 | `String?` | `String \| Nil` の省略形 |
| 合併 | `Int \| String \| Nil` | |
| タプル | `[Int, String]` | 長さと各要素の型が固定 |
| 手続き | `(Int, String) -> Bool`、`() -> Void` | ブロック・lambda の型 |
| トップ | `Object` | すべての型のスーパータイプ |
| ボトム | `Nothing` | `raise`、`exit`、無限ループの型。すべての型のサブタイプ |
| 捨てる結果 | `Void` | 結果の位置だけ(`-> Void`、`(Int) -> Void`)。本体の値を捨てて呼び出し側は `nil` を受け取るので、呼び出しの型は `Nil`。`(Int) -> Void` は `(Int) -> Nil` と同じ型。値の型ではない: `Void?`、`Array[Void]`、`Void` 型の引数はエラー |
| 型変数 | `T`、`K`、`V` | 宣言した型パラメータ |
| 自己型 | `Self` | 受け手のクラス(クラスメソッドではそのインスタンス: `def self.build -> Self = new`)。メソッドが値を渡す側の位置で使う: `def dup -> Self`、`&: (Self) -> Void`。呼び出し側が値を渡す位置(引数、ブロックの戻り値)には使えない(サブクラスに親の値が渡ってしまうため)。そこでは型引数を使う(`Comparable[T]`)。本体の中の `Self` は、そのクラスかサブクラスのどれかで、どれかは分からない。`Self` になるのは `self`、それに対する呼び出しが `Self` として返すもの、クラスメソッドで受け手に対して呼んだ `new` だけ(`Shape.new` は `Self` ではない) |

式の文脈で `Array[Int]` と書くと型そのものを指す式になり、`Array[Int].new` のように使えます(Ruby の `Array.[]` によるコンストラクタはありません)。

## 2. 組み込み型

| 型 | Ruby での対応 | 備考 |
|---|---|---|
| `Nil` | `NilClass` | 値は `nil` のみ |
| `Bool` | `TrueClass`/`FalseClass` | `true`/`false` |
| `Int` | `Integer` | **64 ビット**。結果が範囲を外れる演算は `OverflowError` を投げます(そのためコンパイル済みコードはどの `Int` も機械語の語のまま扱えます)。負の指数(`2 ** -1`)は `ArgumentError` です(`2.0 ** -1` は `0.5`)。整数リテラルは `Int` です |
| `Integer` | `Integer` | **任意精度**。`Int` との演算の結果は `Integer` です。`Int` が `Integer` になるのは明示したときだけで(`to_integer`)、リテラルは `Integer` が期待される場所か、`Int` に収まらないときに `Integer` になります。`Integer#to_i` は収まらない値で `OverflowError` を投げます |
| `Int8`..`Int64`、`UInt8`..`UInt64` | - | 固定幅整数(*予定*)。あふれると例外(`--release` では未定義ではなくラップ、ではなく常に例外) |
| `Float` | `Float` | IEEE 754 倍精度 |
| `Float32` | - | FFI と数値計算向け(*予定*) |
| `String` | `String` | 不変。常に UTF-8 |
| `Bytes` | 文字列(ASCII-8BIT) | 不変のバイト列 |
| `Symbol` | `Symbol` | |
| `Array[out T]` | `Array` | 不変 |
| `Hash[K, out V]` | `Hash` | 不変・挿入順保持 |
| `Set[out T]` | `Set` | 不変 |
| `Range[T]` | `Range` | |
| `Regexp`、`MatchData` | 同名 | |
| `Proc` = `(A...) -> R` | `Proc` | 手続き型の総称 |
| `Enumerator[T]`、`Lazy[T]` | 同名 | 外部イテレータ(`Lazy[T]` は*予定*) |
| `Channel[T]`、`Task[T]`、`Atom[T]`、`Scope` | - | 並行プリミティブ |
| `Array::Builder[T]`、`Hash::Builder[K, V]`、`String::Builder`、`Bytes::Builder`、`Set::Builder[T]` | 可変の `Array` など | 可変・タスク局所 |
| `Class` | `Class` | `obj.class` の型(型引数なしで書く)。`name` などごく限られたリフレクション |

数値の演算は Ruby と同じ意味です。`7 / 2` は `3`、`-7 / 2` は `-4`、`7 % -2` は `-1`、`1 + 1.5` は `2.5`。混在演算は `Int#+(Float) -> Float` などの多重定義として定義されています。固定幅整数(予定)と `Int` の混在は暗黙には行わず、`to_i`/`to_i64` などで明示的に変換する予定です。

## 3. ジェネリクス

```ruby
class Stack[T]
  @items: Array[T] = []
  def push(x: T) -> Stack[T] = Stack[T].from(@items.push(x))
  def peek -> T? = @items.last?
end

def max_by[T, U <: Comparable[U]](xs: Array[T], &key: (T) -> U) -> T?
  ...
end

module Container[out T]      # 共変
  abstract def get -> T
end
```

- クラス、モジュール、`data`、`enum`、メソッドが型パラメータを持てます。
- 上限は `T <: Comparable[T]` と書きます。`T` は `Comparable[T]` かその部分型です。複数は `&` でつなぎます: `T <: Comparable[T] & Describable`(任意のモジュール)。上限 `<:`・下限 `>:`(下記)は Scala・Julia と同じで、同じく反射的です(`T <: X` は `T` が `X` そのものでもよい)。変位の `out`/`in` は RBS と同じです。
- 変位は `out`(共変)/`in`(反変)で宣言し、無印は不変です。コンパイラは現れる位置を検査します。共変のパラメータは値が出ていく位置(戻り値、メソッドが受け取るブロックの引数、下限)にだけ、反変のパラメータは値が入ってくる位置にだけ現れてよく、どちらも `var` フィールドには使えません。不変フィールドの型は戻り値の位置として扱います(リーダーやパターンで読み出されるため)。スーパークラスや include したモジュールの型引数も同じです(値はそれらとして使えるため)。`initialize`、クラスメソッド、private メソッドは正確な型を知っているので検査しません。
- メソッドの型パラメータには**下限** `U >: T` を付けられます。`U` は `T` かその上位型です(上限と併せるときはどちらの順でもよい: `[U >: T <: Object]`)。共変な型はこれで値を受け取ります。`Array[out T]` は `push[U >: T](value: U) -> Array[U]` を持つので、`[1].push("a")` は `Array[Int | String]` になり、`Array[Object]` として見た `Array[Int]` 自体に `String` が入ることはありません。型引数を書かなければ、`U` は下限と、引数が `U` の位置に渡す型の join です。値を探すだけのメソッドは代わりに `Object` を取ります(`delete(value: Object)`、`-(other: Array[Object])`)。
- メソッドの型引数は呼び出し時に推論されます。明示したいときは `max_by[Person, Int](people) { |p| p.age }`。
- 実装は**単相化**(monomorphization)を既定とし、`Int`/`Float` などの非ボックス型についてはそれぞれ専用のコードが生成されます。参照型どうしはコードを共有します。インタプリタでも同じ方針です(予定。今はジェネリックなコードをタグ付きの値に対して 1 度だけコンパイルする)。

## 4. 合併型と nil 安全性

```ruby
def find(id: Int) -> User?
  users[id]?
end

user = find(1)
user.name              # エラー: User? に name はない
user.name if user      # OK: 絞り込み
user&.name             # String?
name = user&.name || "anon"
u = find(1) || raise NotFound    # raise の型は Nothing なので u は User
```

- `nil` は `Nil` 型の唯一の値で、他のどの型の値でもありません。
- `T?` は `T | Nil` の糖衣です。`Int | String | Nil` のような任意の合併型も書けます。
- 合併型の値に対して呼べるのは、すべての構成型に共通する(かつ戻り値型が互換な)メソッドだけです。それ以外は絞り込んでから呼びます。
- 合併型は正規化されます: `Int | Int` → `Int`、`Int | Object` → `Object`、`(Int | String) | Nil` → `Int | String | Nil`。

## 5. 型推論

推論は**双方向・局所的**です。メソッドの引数型が既知なので、推論は 1 メソッド本体で閉じ、プログラム全体の推論は行いません。

- **ローカル変数**: 最初の代入の型。`x = 1` なら `Int`。
- **戻り値型**: 推論せず、宣言します。宣言のないメソッドは `-> Void` です(Swift の `->` のない `func` が `Void` を返すのと同じです)。本体の最後の値は使わず、nil を返します(出力する `def report`、`def test_pop`、セッターなど)。`-> Nil` は他の型と同じく厳密で、本体は `Nil` を返さなければなりません。`=` で定義するメソッドは値を返すものなので、型を宣言します(`def area -> Float = w * h`。`def area = w * h` はエラーです)。`abstract def` と `extern def` も宣言します。`-> Void` のメソッドで値のある `return x` はエラーです。オーバーライドは、上書きするメソッドの型かそのサブタイプを返します(共変です。`-> Object` を `-> Int` で上書きできます)。そのため、`-> String` のない `def to_s` はエラーです。呼び出し側に必要なことはシグネチャがすべて表すので、各ファイルを単独で検査でき(05-execution.ja.md §2)、メソッドの型が別のメソッドの本体に左右されることはありません。
- **空リテラル**: `[]`、`{}`、`Set[]` は期待型があればそれに従い、なければ `Array[?T]` のような型変数を持ち、同じメソッドの中のあとの使い方で決まります。型変数を決めるのは値の使い方(型の決まった場所への代入、引数、`push` など)だけです。まだ型の決まっていない値をパターンや型の判定で絞り込むのはその分岐の中だけで(そのような値の `case`/`in` は `else` がなくても網羅的とみなします)、値を使わない `if` は分岐の型を合わせず、他の型と合わせても型変数は決めません(`x = xs[0] if c` は `?T?`、`xs[0] || "s"` は `?T | String`)。そのような union に `Object` 以外のメソッドを呼ぶのは使い方の一つで、`?T` を残りの型に決めます。

```ruby
counts = words.reduce({}) { |h, w| h.put(w, h.fetch(w, 0) + 1) }   # {} は Hash[String, Int]
names: Array[String] = []          # 期待型から
xs = []                            # ここではまだ Array[?T]
xs = xs.push(1)                    # ここで決まり、xs は Array[Int]
```

- **ブロックの引数**: 渡し先の `&block` の型から決まります。`[1, 2].map { |x| x * 2 }` の `x` は `Int`。
- **ジェネリックメソッドの型引数**: 引数とブロックの型から単一化で決まります。
- **数値リテラル**: 期待型が `Float` なら `1` は `Float` として扱われ、期待型が `Int32` なら `Int32` になります(固定幅整数ができてから)。既定は `Int`/`Float`。オーバーロードの中では、各リテラルを既定の型にして当てはまるものが先です(`x + 1` は `Int#+(Int)`、`1.5 / 2` は `Float#/(Int)`。docs/01 §9)。
- **タプルと配列**: 配列リテラルは期待型(タプルか配列)に従います。期待型がなければ、要素の型を合わせると合併型になるときはタプル、共通の型があるときは配列です。`[w, w.size]` は `[String, Int]`、`[1, 2]` は `Array[Int]`、`[circle, rect]` は `Array[Shape]`。`return a, b` と多重代入の右辺も同じ規則です。タプルは要素の型を合わせた型の配列でもあるので、配列のメソッドが使えます。要素がすべて比較できるタプルは、要素ごとに比較できます(`<`、`<=>`、`sort`、`max`)。比較できる型を要素に持つ配列も同じです。タプルのリテラルを代入したローカル変数(`t = [1, "a"]`)は、その配列の型で宣言され、タプルに絞り込まれます。`t[0]` は `Int` で、`t = t.push(2)` もできます。

## 6. フロー型付け(絞り込み)

条件分岐によってローカル変数の型が絞り込まれます。

```ruby
def describe(x: Int | String | Nil) -> String
  return "nothing" if x.nil?          # 以降 x: Int | String
  if x.is_a?(Int)
    "int #{x + 1}"                    # x: Int
  else
    "str #{x.upcase}"                 # x: String
  end
end

case v
in Int => n then n + 1
in String => s then s.size
end

while (line = io.gets?)             # line: String(ループ内)
  puts line
end
```

絞り込みが効く条件: 真偽判定(`if x`)、`x.nil?`、`x.is_a?(T)`、`x in Pattern`(真の分岐だけ)、`case/in`、`nil`、`true`/`false`(等しい側が `Bool` になる)、enum の空バリアント(等しい側がそのバリアントになり、等しくない側からは除かれる)との `==`/`!=` による比較、`&&`/`||`/`!`/`and`/`or`/`not` の組み合わせ、`return`/`raise`/`next`/`break` による早期脱出、代入。

判定が絞り込むのは、判定が通ったときに確かに成り立つ型までです。数のパターンは他の数のクラスの等しい値にも一致します(`Int | Float` に対する `in 1` は両方を残します)。`nil`、`true`/`false`、バリアントとの比較が絞り込むのは、サブクラスを持てない型(組み込みの値のクラス、`data` 型、enum とそのバリアント、およびそれらの合併型)で、`==` と `!=` が組み込みのものである値だけです。クラスやモジュールには、別にコンパイルされるファイルで独自の `==` を定義するサブクラスがありうるので、`x == nil` は `Foo?` を絞り込みません(`x.nil?` や `if x` は絞り込みます)。パターンや `when` に型引数なしで書いたジェネリッククラス(`in Box`、`when Box`)は、型引数を値の型から取ります。値の型から分からないとき、`Object` は、`Object` を型引数にしても誤った値を受け付けないクラス(組み込みのコレクション、型パラメータを共変にしか持たない `data`、型パラメータが共変で上限を `Object` が満たすクラス。`is_a?` と同じです。§7)にだけ絞り込み、それ以外では `Object` のままです。組み込みの値のクラス(`Int`、`String`、`Array` など)はサブクラスを持てません。

絞り込まれるのは**ローカル変数、不変フィールド(`@x`)、`data` のフィールド**です(`data` の本体の中で `@name` として読んだとき。`p.name` のような読み出しはメソッド呼び出しです)。`var` フィールドや任意のメソッド呼び出し結果(`user.name`)は、途中で変わりうるので絞り込まれません。一度ローカル変数に受けてください。可変フィールドを持たない設計が既定なので、Ruby の `@x && @x.foo` のような慣用句の多くはそのまま通ります。

クロージャはローカル変数を参照で捕まえるので、あとで実行されうるクロージャ(ラムダ、ブロックを保持しうるメソッドに渡したブロック。01-syntax.ja.md §9)は絞り込みを制限します。そのクロージャが代入するローカル変数は、クロージャを作った時点から絞り込まれません(どの呼び出しでも実行されうるため。文字列の式展開の `to_s` のような暗黙の呼び出しも含みます。ループの中や `rescue` が `retry` する本体の中なら、その先頭から)。また、そのクロージャの中では、実行されるまでに変わりうるローカル変数(2か所以上で代入される、`while` ループの中で代入される、代入されるパラメータ、`!` メソッドで束縛し直される)は、外側の検査では絞り込まれません。イテレータのブロックのように `yield` で呼ばれるだけのブロックは呼び出しの間に実行されるので、どちらの制限も受けません。`each` のブロックで `found = x` としたあとの `if found` は `found` を絞り込みます。再び実行されうるコード(ループの本体、ブロック、ラムダ)は、そのブロックを渡す先のメソッドがまだ分からないうちに、検査の前に調べます。そこではどのブロックもあとで実行されうるものとみなすので、ループの中のブロックで代入するローカル変数は、ループの本体では絞り込まれません(`while` の中の `each` のブロックで `last = v` としたあとの `if last` は `last` を絞り込みません。ブロックの結果を代入してください)。クロージャの中で初めて代入されるローカル変数は、本体があとで同じ名前に代入しても、そのクロージャのものであり、ほかと同じように絞り込まれます。あとの入力が追加されていく REPL のトップレベルでは、ラムダの中で外側のローカル変数は絞り込まれません。

## 7. キャスト

```ruby
n = obj.as(Int)         # 失敗すると TypeError
n = obj.as?(Int)        # Int?
f = n.to_f              # 変換メソッド(キャストではない)
```

ダウンキャスト(`as`、`as?`、`is_a?`)は実行時に検査します。組み込みのコレクションとタプルは要素も検査します(`obj.as(Array[String])` はすべての要素を調べます。空の配列は通ります)。それ以外の型引数は実行時に検査できないので、`obj.as(Box[Int])` は、`obj` が `Box` であるなら必ず `Box[Int]` である場合(`Box[Int]?` など)を除いてエラーで、`is_a?` も同じです。共変で上限が `Object` を許す型パラメータへの `Object` 引数は検査が要りません(`Box[out T]` に対する `obj.is_a?(Box[Object])`: どの `Box` もそうです)。安全でない再解釈キャストは FFI 層(`Pointer#cast`)にしかありません。

## 8. メソッド解決と多重定義

- 呼び出しはレシーバの静的型で解決されます。候補は、そのクラス、スーパークラス、include したモジュール、スコープで有効な `extension` のメソッドです。
- 祖先の順序は Ruby と同じです。クラス、そのクラスが include したモジュール(後に include したものが先で、それぞれの後にそれが持ち込むモジュール)、スーパークラスの祖先の順です。すでにあるモジュール(先に include したモジュールやスーパークラスの側から来たもの)を include しても何も起きず、そのモジュールは最初に include したものの下に留まります。`class Base; include M; end`、`module N; include M; end`、`class Child < Base; include N; end` のとき、Child の祖先は `Child, N, Base, M, Object` なので、Child でも Base のメソッドが M のものを上書きします。スーパークラスの側に別の型引数で入っているジェネリックなモジュールは「すでにある」ものではありません。A が `Comparable[A]` を include していて `class B < A; include Comparable[B]; end` のとき、`Comparable[B]` が B のすぐ後に入り、A のものは除かれます。
- 同名メソッドの多重定義があるときは、引数の個数、キーワード、型によって最も特定的なものが選ばれます。曖昧ならエラーです。(現状では、宣言順で最初に合う多重定義が選ばれ、曖昧さは報告されません。)
- サブクラスで上書きされうるメソッドは仮想呼び出し(vtable)になります。クラス階層はプログラム全体で確定するため、上書きのないメソッドはリンク時に静的呼び出しへ置き換えられます(クラス階層解析)。
- モジュール型のレシーバへの呼び出しはインターフェース呼び出し(クラスごとのモジュール実装テーブル)です。
- `respond_to?` はコンパイル時定数に畳まれます。`send`/`public_send`/`method`/`define_method`/`method_missing`/`instance_variable_get` は存在しません。

## 9. Shareable(共有可能性)

`Shareable` は「他のタスクに安全に渡せる型」を表すマーカーモジュールです。`data` と `enum` については、コンパイラがフィールドから導出します。クラスとモジュールは `include Shareable` で宣言し、コンパイラはそのクラスと、それを継承または include するすべてのクラスが規則を満たすか検査します。詳細は [03-data-model.ja.md](03-data-model.ja.md) §5 ですが、型システムの観点では次のように使われます。

```ruby
class Channel[T <: Shareable]
class Atom[T <: Shareable]
def self.spawn[T <: Shareable](&block: () -> T) -> Task[T]   # ブロックの捕捉変数も Shareable である必要がある
```

`include Shareable` は、サブタイプも守る約束です。Shareable な型の値は、どのクラスの値であっても Shareable です。そのため、型が Shareable かどうかは、その定義の場所で、自身と祖先の宣言だけから決まります。プログラムの残りを見る必要はありません(分割コンパイルにはこれが必要です)。

手続きの型は Shareable ではありません。ブロックは周りのコードの変数を読み、代入しますが、それを別のタスクがしてはいけないからです。Shareable な手続きの型は `shareable (A) -> R` です。この型が期待される位置(ブロック引数 `&job: shareable (Int) -> Void`、引数、型注釈のある変数)に書いたブロックやラムダは、`Task.spawn` のブロックと同じく値で捕捉します。読む変数は作った時点でコピーされ、その値は Shareable でなければならず(`self` を使うなら `self` も)、それに代入することはできません。そうした手続きは、どのタスクからでも、ほかと同時に呼べます。ワーカープールやサーバーのループは、それを受け取り、自分のタスクで動かせます。

```ruby
def each_in_tasks(n: Int, &job: shareable (Int) -> Void) -> Void
  Task.scope { |s| n.times { |i| s.spawn { job.call(i) } } }
end
label = "item"
each_in_tasks(3) { |i| puts "#{label} #{i}" }    # `label` をコピーする
log: shareable (String) -> Void = ->(s: String) { STDERR.puts(s) }
```

Shareable な手続きは手続きです(`shareable (A) -> R` は `(A) -> R` のサブタイプ)。逆は成り立たないので、`g = ->() { 1 }` に対する `f: shareable () -> Int = g` はエラーです。ラムダを書く位置で型を注釈してください。

## 10. 採用しなかった案

- **構造的型付け(Go のインターフェース、TypeScript)**: ダックタイピングに近く魅力的ですが、Ruby では「`each` を持つ」だけでなく「`each` の意味」を期待しています。名前的なモジュール + `extension` による後付け適合で同じ柔軟性を得つつ、適合の意図を明示させる方を選びました。
- **動的型 `Dynamic`**: 試作時の手軽さのために検討しましたが、1 つでもあるとすべてのクラスに実行時メソッドテーブルが必要になり、インタプリタと AOT の両方で最適化を妨げます。試作の手軽さは推論の強化で得ることにします。
- **全体推論**: 引数型を省けますが、コンパイル時間とエラーメッセージの質が犠牲になります。「メソッドの境界では書く」が Quarz の割り切りです。
